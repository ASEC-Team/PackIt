    Dictionaries and Lists

    Let's gradually define a Player's data as an approach on how to use the framework. This is not an actual usage of player data

    We'll define a dictionray with Username and UserId for our Player. 

    local dict = PackIt.dict("Player")

dict:varchar("Username") -- BYTE Lenght string
    :id("UserId") -- Positive float64

dict:Build()

    We now want to make the player own a list of items, so we are going to define a list of items ids inside it. Since we are appending to the bottom of the dictionary we dont have to make a new variant. Works for nested dicts aswell with Nested serialization mode.

    dict:list("Items", function(list) -- {Positive float64}
    list:id({
        Sanitizers = { -- Positive check is builtin in the type, custom example:
            function(v, t) assert(v > 0, "Invalid Id") end
        }
    })

end):Build()

    Now we want to associate a price to each item (max ~42 mil and defaults to 0, can have 2 digit decimals), we want to change old list to include it without corrupting previous data, so we are going to use versioning. (Migration must be handled somewhere in this case)

    local variant = dict:Variant()

variant:list("Items", function(list)
    list:dict(function(dict)
        dict:uint("Price", {
            Size = "DWORD", -- Max 4.294.967.296
            Default = 0, -- Defaults to 0
            Round = .01 -- Store decimals into uint

        }):id("ItemId")
    end)
end)

variant:Build()

    To create a list of players, you can pass the existing schema directly to a list container. Keep in mind that reusing an external schema adds a small amount of overhead compared to an inline schema definition. This example doesnt really need nested mode as there is no nested dictionary in another dictionary yet.

    local options = {
    Mode = "Nested" -- "Flat" by default
    -- Do not use Compress in sub-schemas
    -- Variant = 1 (Highest by default)
    -- Engine = 1 (Highest by default)
}

local list = PackIt.list("Players")
list:schema(dict, options) -- Options are not inherited form list to variant
list:Build() -- dict is logically equivalent to variant

    Lets now Serialize and Load the data.

    local options = {
    Compress = { Type = Enum.CompressionAlgorithm.Zstd },
    Mode = "Nested"
}

local versioning = {
    -- Variant = 1 (Highest by default)
}

local template = list:Template(versioning) -- Generates mock data
local buffer = list:Serialize(template, options) -- Still not inherited in sub-schemas
local data = list:Load(buffer, versioning) -- Deserialized data

    Tuple Variants

    Although Tuples are effectively dictionaries that use numeric indexes as keys, their manipulation is handled differently than standard dictionaries or lists.

    Consider a tuple describing an item's Name, Quantity, and Price:

    local tuple = PackIt.tuple()

tuple:varchar() -- Index 1: Name
    :uint()     -- Index 2: Quantity
    :uint()     -- Index 3: Price

tuple:Build()

    Now, suppose we want to create a variant that modifies the numeric size of Quantity and Price without overriding the Name field.

    We can pass an Index within the Tuple field Options to explicitly target specific positions:

    local variant = tuple:Variant()

variant:uint({      -- Quantity
    Size = "Word",
    Index = 2,      -- Target index 2 explicitly
}):uint({           -- Price
    Size = "DWORD"  -- Index automatically increments to 3
})

variant:Build()

    Finally, we can construct template mock data, serialize it, and deserialize the resulting buffer:

    local template = variant:Template(versioning) -- Generates mock data -> ("", 0, 0)
local buffer = variant:Serialize(template, options)
local data = variant:Load(buffer, versioning) -- Deserialized data
